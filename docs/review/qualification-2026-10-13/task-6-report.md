Reloading worked. That exact observed sequence is the evidence; it does not imply the tests or prior static proof covered this race.

The source selected active immediately when register returned no installing/waiting worker. The W3C Service Workers algorithms explain why this is insufficient: Register may resolve an unchanged registration immediately, whereas explicit Update completes its script check and assigns installing before resolving when a changed worker is found. Source: https://w3c.github.io/ServiceWorker/#register and https://w3c.github.io/ServiceWorker/#installation-algorithm (consulted 2026-10-12).

Correction: when neither waiting nor installing is visible and the browser does not report offline, await registration.update() within the existing 15-second preparation bound, then re-read all worker slots and await installation state as before. No artificial delay or event polling. Known offline skips the network check; a rejected network check retains access to an active training worker and its cache status/removal. Timed-out preparation rejects and late update completion cannot send a message. No activation, cache-policy, score, progress, or focus contract changed: only explicit fully verified download activates the new worker.
